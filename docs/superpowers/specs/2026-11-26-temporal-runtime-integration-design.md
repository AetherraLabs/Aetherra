## Intent and boundaries

Connect completed numeric Core observations to the existing TemporalConsciousnessEngine through authoritative typed Memory history. Default disabled; Aetherra remains the persistent system, Lyrixa its persona. No replies, autonomous actions, forecasts, causal reasoning, model calls, new database or checkpoint schema changes. Preserve standalone engine callers, protected original Temporal/alpha work and signing enforcement.

## Approach

Use a separate daemon collector and the existing Memory lane. A synchronous Core callback would couple progress and shutdown; the preserved prototype's generic replacement checkpoints would create a competing authority. Neither fits the approved contract. The collector owns one engine and applies only acknowledged or validated durable evidence. Its callback/source/engine work cannot run on chat's asyncio loop.

Configuration is a strict root `temporal_observer` object: `enabled` boolean; when true, a 32-lowercase-hex `history_id` and explicit `start_mode` (`create` or `resume`). Unknown keys and inconsistent disabled options fail closed for Temporal. Enabled requires explicitly enabled observe-only Core and real exact-owned Memory. Enable the Core source at construction for a valid request, without adding Temporal ownership to Core readiness. Temporal configuration or policy failure is visible separately and does not disable otherwise healthy Core/chat. No automatic takeover/reacquisition after runtime ownership loss.

## Engine import

Add `import_history_window(records, *, history_id, selected_head, authorize, publication_guard=None)` and `get_history_status()` to the existing engine. Input is a tuple of at most 256 canonical typed HistoryRecords ending at the exact selected HistoryHead; empty is valid only for an empty head. Validate contiguous ordinals/digests, history identity, duplicate IDs, representable UTC timestamps and frozen schema before mutation. A nonempty suffix beginning after ordinal one is explicitly partial, not global archive verification.

Build a candidate, call the supplied current-authority check immediately before publication, and reject reentrant mutation through the existing revision mechanism. An optional local-only publication_guard context manager linearizes the final assignment against local cancellation; run all candidate construction and external authorization before entering it. Do not hold its lock across policy, Memory, engine callbacks or I/O. Runtime supplies real Memory job restore-policy, local owner, stop/deadline checks; a caller callback does not itself grant authority. Retain exact opaque record IDs as moment IDs. Only observations become moments; use only the three numeric counts. Order/eviction follow committed ordinal despite wall-clock rollback. Preserve raw clocks/source/digest provenance in the bounded derived cache. No heuristic associations, chains or predictions are generated. Legacy standalone mutation/checkpoint APIs reject mixing with imported runtime state; untouched standalone use retains its behavior. The archive remains in Memory without deletion.

## Collector and recovery

The collector polls the cached completed-Core source at most once per five monotonic seconds. Deduplicate source session/sequence, report skipped sequences, and save only changed numeric counts plus session/gap/end boundaries. Source unavailable or changed becomes a marker only when another verified observation is available; no invented numeric sample. First saved batch is start+observation, or start+restart-gap+observation for resumed nonempty history. End marker anchors the exact last durable observation and means collector closed, not OS shutdown. Do not write an end marker before the current epoch has successfully saved an observation. Resume of the same Core source waits for a strictly newer sequence than its last durable source. Validate live source/session/capture UTC clocks are datetime-representable before appending, so invalid source data cannot poison restoration.

Acquire/fence through typed Memory before accepting observations. Restore a suffix of at most 256 records in pages of 64. Do not publish restored engine state until all selected pages are validated and a current accepted job's policy/ownership window is rechecked immediately before atomic import. Restore corruption, missing, denial, expiry or unavailable storage blocks collection; never silently reset to empty. During live operation, append receipts pass the same authority/import path. Preserve the window and advance it only with an accepted exact receipt. Probe the current token with a bounded governed read each unchanged/unavailable sampling interval so takeover is detected even without writes; do not reacquire.

At most one collector job is active. Each attempt uses existing CheckpointJobControl's at-most-one-second deadline and local StreamJob polling. Timeout/late completion is terminal uncertain for that runtime, with pending ownership retained until settlement. No retry, fabricated acknowledgement or automatic epoch acquisition. The epoch is last verified by Memory: another process may fence after its result and before volatile engine publication. Such a publication is last-verified evidence, not a guarantee of current cross-process ownership; the next governed probe detects takeover and stops collection. An explicit new `resume` restores the current verified durable head after fencing; it does not claim that an earlier unknown operation was individually resolved. Exact original-operation resolution remains available through Memory's typed inspect interface, not inferred from absence or elapsed time.

## Shutdown and status

Close observation admission synchronously before every Core orderly/graceful/emergency stop path, including direct Core monitor replacement/error stops. Retain the original Temporal instance and backend independently of mutable registry/system entries. If Core stop/drain fails, suppress the final marker and preserve pending cleanup instead of declaring orderly continuity. Core retains its original two-second deadline and priority. Only after Core stop/drain, request an independently bounded (one-second) Temporal final marker/drain. Repeated cleanup uses the original deadline and backend; unresolved work remains visible and makes cleanup pending. A failed/uncertain/fenced collector does not write an end marker or claim a clean persistence stop. Do not wait for a blocked Temporal engine, policy callback or Memory operation on chat's asyncio loop.

Cache bounded status under a short lock: enabled/state, accepted/skipped counts, source freshness, selected/restored/saved record IDs, writer epoch and last-verified ownership, outstanding/persistence state, error code, source clocks and gap interpretation. Exact epochs are last verified, never a timeless ownership guarantee. Wall-time gap is only an estimate, rollback is inconsistent, offline duration unknown. Getters perform no engine, policy, audit or Memory calls. Lost source/ownership and expired cache cannot retain healthy status.

Register only an exact-owned optional Temporal service. Expose allowlisted scalar status through the existing Consciousness inspector and existing Hub snapshot surfaces; keep Core and Temporal health separate. Disabled, blocked, missing, unavailable and stopped states stay distinguishable. UI clears old live values when transport is unavailable. No new chat context, endpoint or scene node. A weak owned status binding on existing HubState distinguishes disabled configuration from absent service evidence, including when Core is disabled. Both owner and registry are weak references; only the exact owner/registry may clear it, and a competing live owner in the same registry is preserved. The provider reads the retained collector cache and local identities only. An unavailable registry clears live projected identifiers without discarding internally owned pending cleanup.
